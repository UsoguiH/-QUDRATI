# قدراتي — QUDRATI

**This is a real, published project. It is live at [qudrati.xyz](https://qudrati.xyz/) and available on Android as `Qudrati.apk`. Treat all changes as production code.**

## What it is

A Duolingo-style Arabic web game for practicing the Quantitative section of the Saudi General Aptitude Test (GAT / Qiyas). Fully RTL, Arabic-first, zero dependencies, zero server, zero build toolchain. Open `index.html` and play.

## Tech stack

- **Pure HTML/CSS/JS** — no npm, no bundler, no framework
- **State**: single `S` object in `localStorage["qudratState"]`
- **CSS**: pixel-perfect implementation of the Duolingo design system (colors/radii extracted from Figma file `sCGqaL307LkNrY35xnV66O`)
- **Font**: Baloo Bhaijaan 2 (Arabic rounded equivalent of Duolingo's DIN 2014 Rounded VF)
- **Android**: Capacitor wrapper → `Qudrati.apk`

## Game systems

- **Structure**: 4 units · 26 lessons (8 / 5 / 4 / 9), unlocked sequentially. A lesson with a learn set (`js/data/learn.js`) is a path node of 6–8 **short lessons** (below); the rest still serve 8 questions behind teaching cards
- **The home screen** (`statbar`, `renderPath`, `drawTrails`, `A.nodeTap`) is **the live site's, exactly** — the user tried a home rebuilt on Duolingo's (top-bar drawers, a sticky unit header, no labels, Duolingo's curve and ring, maths tiles beside the path) on 2026-10-22 and asked for qudrati.xyz's back on 2026-10-23 («exactly like the photo»); do not rebuild it on Duolingo's again without being asked. **Stat bar**: the streak, the rank badge with its name, the gems. Under it `countdownCard()` (the exam card), then `dueCard()` (review / streak at risk / the mix), both in the path's 16px-inset box. **The unit banner** is a button (`.unit-banner`, → `A.openUnitBook`, the unit's rules; its width is set, since a button shrinks to its text and short unit names came out narrow): «القسم ١، الوحدة N» over the unit's name, a divider, and «N/M دروس» on the far side (`.u-side`, `.u-divider`, `.u-prog`), sticky under the stat bar. **The nodes** (`.node-col` > `.node`) wind on `offsets` (0, −46, −66, −46, 0, 46, 66, 46), each with its title under it (`.node-label`), joined by a dotted trail (`drawTrails`); done is gold with its three stars under it (drawn as stars, `LESSON_ICON_STAR` — as dots they read as a coin's change and sat on the title), open in the unit colour, locked grey; a lesson not played in a fortnight dims and wears a refresh mark (`stale`). **Each lesson has its own sign where the star was** (`LESSON_ICON`, `lessonIcon`, `.node-ic`; the user, 2026-10-23: «change stars to something else, and each level something different»): 26 glyphs on a 40-unit square in the star's weight (`.s` stroke, `.f` fill, `.j` both) — the four operations, a key, a die, a bolt, repeat arrows, scissors, a balance, two circles; two boxes and a dot, a fraction, √, a power, a stopwatch; ٪, a price tag, up and down arrows, bars and their mean; an angle, a triangle, a rectangle, a square with its right angle, a parallelogram, a shaded square, a circle with its radius, parallel lines, a cube — white on the face, brown on a gold node; a new lesson key falls back to the star (`LESSON_ICON_STAR`). The current node bobs inside **Duolingo's segmented ring** — one segment per short lesson with a gap between, done ones in the unit's colour, the rest grey, drawn from the top round to the left (`ringSvg`, `RING_D`, `ringSeg`, `.ring-seg`, `.ring-arc` / `.ring-track`; a node without short lessons wears one whole grey ring) — under its «ابدأ» / «كمّل» tooltip (a white pill with a centred, clipped square tail: `.node-tip`, `::after`); the chest floats beside the path (`floatingQuest`). **The popover** (`A.nodeTap`): the purple sheet with the lesson's name, «الدرس ٢ من ٦، …» (`.lp-sub`), the 2× boost (`.lp-boost`) and a white button. **Duolingo's three node beats** (timed frame by frame from `node_and_ring_119.riv`; the user, 2026-10-23: «exactly like Duolingo's effects»): **press & open** — measured off Duolingo's file like the lesson done (the user, 2026-10-23: «do it correctly like Duolingo»): the face drops its whole lip in one frame while held (`.node:active`, no transition; the desktop hover lift is `:not(:active)`, or a mouse — always hovering as it presses — never sees the press) and comes back on the release with Duolingo's two-step settle (`nodeRelease`); the ring breathes on Duolingo's two-second loop (`ringIdle`, `ringDimTrack`, `ringDimArc`: out to 1.02 and in to .86 × .82 of Duolingo's own size, carried onto ours against the coin, fading as it pulls in); opening the card pulls it in behind the coin and fades it, then lets it out a little to wait (`ringSelect`, `RING_SEL`, `.node-col.sel`), and closing picks the breathing up from that size (`ringResume`). Duolingo's press, release and close sounds play with it (`A.nodePress`, `sfxPlay`); the lab's card starts its ring at `ring_starting_state_num` 0, the state that breathes; **the star flip** — every six seconds the current node's icon lifts out of the coin over its own shadow and turns once while the ring stretches and shrinks (`nodeFlip`, `nodeFlipLoop`; paused while a card is open, ends off the path); **a lesson done** — `lessonComplete` sets `PATH_PAY` (`{ key, was, gold }`) for every short lesson finished for the first time and every first clear, and `pathPay` plays it once on the path. It is Duolingo's `node_complete_trig` **copied frame by frame** (the user, 2026-10-23: «100% clone it exactly»): the file was played at a tenth of its speed and the coin measured every 17ms. `PAY_COIN` holds those rows in Duolingo's own pixels (face top, face height, rim offset, width, paint), `PAY_ICON` the sign shrinking out and growing back, `PAY_GHOST` its shadow (`.node-ghost`, `--node-ghost`), and `PAY_DIAS` its three rounded diamonds (`.node-dia`). In 1.56s: it squats, springs off its shadow tall and narrow, hangs while the diamonds slide out from behind it, tips over until it is seen edge-on from underneath (rim over the top, then a dark underside under a light band), comes back the right way up (gold, on the node's last lesson) with its sign growing, rises, stretches, drops, squashes and settles. Duolingo's own `node_complete` sound (`assets/sounds/node-complete.mp3`, from `node_complete_l3.ogg`) starts on the take-off at 136ms. **Which beat plays**: a short lesson done plays Duolingo's ring only (`ringPay`, from `ring_return_to_path` + `ring_lesson_complete`, measured the same way): the ring comes back from .74 of its size with its segments fading in, the earned segment lets its grey go, the colour runs along it in 135ms, three diamonds pop off its end and drift out, then the star turns over. The coin jump above (`coinPay`) plays only on the node's last lesson, after the ring fills and lets go. The «كمّل» bubble steps aside and pops back; the star flip waits (`payRun`). **Re-pressing the node while its card is open** lands on the veil, which presses the node itself (`.node.down`) so the press never lags. `preview.html#pathpay` / `#pathgold`. The tab bar: 1px line, 40px buttons (`--nav-h` 80). Node shapes to replace the coin are being discussed in `tools/pills.html` — nothing from it is in the app yet
- **Short lessons** (`js/data/learn.js`, `A.startLearn`, `renderLearn`, `learnCheck`, `learnResolve`, `learnFinish`): the user found the old lessons boring, unclear and far too long (a node was a whole book chapter: bigsum = 13 rules read off cards, then 8 timed exam questions). A short lesson is ONE idea in about three minutes, taught by doing — «اكتشف ← جرّب ← ثبّت ← تحدَّ»: a free guess (`free`: no heart, not counted), a `see` card that unfolds the trick row by row in big numbers with a one-line `rule` (the rule card is **Duolingo's regular yellow** — `--gold-bg` on a 2px `--gold` border with a 5px bottom edge, the bulb in a `--gold` badge, «القاعدة» and ↻ in brown, the rule in ink; the user, 2026-10-23, after a solid gold card and then a green one: «make the law yellow — not the last yellow, the regular Duolingo yellow — and the things in the law in blue». The things a rule is about are marked `*…*` in learn.js (all 57 rules are marked: «*العدد*», «*آخر عدد*», «*الزيادة الأكبر*» — keep marking new ones). The card springs in after the last row and says the rule a word at a time (`ruleWords`, `.rw`, 110ms apart), the signs = × ÷ + − ← a size up in `--gold-dk` (`.rw.op`); then each marked term — one chip however many words it has — lights as a blue chip like the lesson's own «اضرب» and «٥» (`--blue-light` under `--blue-dk`, the user's ask the same evening), one after another, each popping on a note a step higher (`.rk`, `rkLit`, `RULE_LIT`), the bulb lights and the card settles with a chime (`rulePlay`); ↻ says it again (`A.ruleAgain`)), a `fill` (the trick's step from tiles), quick reps in several shapes (`pick` with a `why` per wrong choice, `tf`, `type` on an Arabic keypad, `pairs`, `order`), then one or more `bank` questions (the real thing, by id — every bank question of a node served exactly once across its lessons). Each lesson after the first opens with one `recall` item from the one before; a missed item comes back at the end with new numbers; the bar never steps back. No timer while learning; no hearts until the first node is finished (`SES.safe`). The node's ring fills one short lesson at a time (`S.learn[key].done`), it earns its stars (and opens the next node) when all are done, and a finished node replays as the old timed bank practice. The win screen shows the node's lessons as pills and offers «الدرس التالي» straight into the next one. Figures: `fig: "@skills.keylaws:9"` borrows a card figure. Validate with `node tools/validate_learn.js`; `preview.html#learn-skills.keylaws-3` opens any one. Every right answer plays the lesson's jump: in `pairs` each matched pair hops with the same beats at a third of the height (`pairHop`, the full jump landed a tile on its neighbour) and greys out, a wrong pair sinks and shakes, and the last pair's win jump plays on the whole board

## Question schema

```js
{
  id: "unique-id",           // e.g. "oo-01" — must be globally unique
  format: "mcq",             // or "comparison"
  difficulty: 2,             // 1=easy, 2=medium, 3=hard
  track: "both",             // "both" | "sci" | "lit"
  stem: "نص السؤال…",
  choices: ["أ","ب","جـ","د"], // mcq only — 4 items, no letter prefix
  // value1: "…", value2: "…", // comparison only
  answer: 0,                 // 0-indexed correct choice
  solution: "الحل خطوة…",   // step-by-step, \n between steps (≥10 chars)
  method: "١) …\n٢) …\n💡 …", // structured method steps (optional but preferred)
  figure: null               // or inline SVG / HTML table string
}
```

Lessons also carry `stars`, `xp`, `pages`, `category`, `goal`, `rules[{n,name,formula,when}]`, `notes`,
`tricks`, an optional `figure`, and a flat `method` string (the fallback the method sheet shows).

Comparison answers must use the fixed 4-choice set defined in `CMP_CHOICES` (app.js line ~12):
`["القيمة الأولى أكبر", "القيمة الثانية أكبر", "القيمتان متساويتان", "المعطيات غير كافية"]`

## Validating the question bank

```bash
node tools/validate.js
```

Checks: unique IDs, valid format/difficulty/track/answer, solution length, figure tag, duplicate choices, comparison answer distribution.
The difficulty ramp is checked by `node tools/validate_teach.js` instead, which knows the chunks: a
student meets a chunk's questions sorted by difficulty, so that validator lists every step wider than
one star as a cliff still to bridge.

**The four data files are generated — never hand-edit them.** To change content, edit
`qudrat-lessons-duolingo.md` and run:

```bash
python tools/import_curriculum.py          # --check parses and reconciles without writing
node tools/validate.js
```

The importer refuses any line it cannot parse and reconciles every count against the
file's own map; a question that says «في الشكل» must have an SVG in `tools/curriculum_figures.py`.

## Adding features

- **Every progress bar is the regular bar.** A bar that fills — a lesson, a goal, a quest — is `.duo-bar` (or the session's `.progress`) with its colour passed as `--bar-c` / `--bar-shine`; never a one-off bar with its own height, radius or shine (the user, 2026-10-23, on «تقدّمك اليوم»: «it must be like the regular bar … even if not in claude.md you should be careful of it»).

- **Every answer jumps — and only answers.** Whenever a student picks or submits an answer to a question — a lesson, a short lesson, a teaching check, the taste question, the level test, the mock exam — the answer card plays the lessons' correct-answer jump (`fxAddJump`, via `obJump` / `teachFx` / the lesson's own fx). A right answer jumps when it is revealed; where no verdict is given (the level test, the mock) the picked card jumps to say «taken». Choices that are not answers to a question (the first run's level, goal and fork, settings) never jump. A new answer UI is not done until it does this (the user, 2026-10-21 and 2026-10-22).

- All rendering is done by functions in `js/app.js` that return HTML strings and set `$app.innerHTML`.
- Navigation: call `A.go(screenName)` — the `A` object exposes all public handlers.
- New screens follow the pattern: render function → attach to `A` → add nav target to `A.go()`.
- CSS variables are at the top of `style.css` under `:root`. Always use them — never hardcode colors.
- Arabic digits: use `toAr(n)` to render numbers in Eastern Arabic (`٠١٢٣٤٥٦٧٨٩`). Use Latin digits only in code/IDs.

## What NOT to do

- Do not introduce any npm packages, bundlers, or build steps — the project ships as static files.
- Do not add `//`-commented-out code blocks or TODO comments in production code.
- Do not use Latin digits in user-visible text (question stems, solutions, UI).
- Do not copy or reproduce real Qiyas/ETEC exam questions — all questions must be original.
- Do not break the RTL layout — test all UI changes with `dir="rtl"`.

## Deployment

Static hosting, no server required. The app is live at **qudrati.xyz**. The Android APK (`Qudrati.apk`) is a Capacitor wrapper over the same static files.

**Bump `VERSION` in `sw.js` whenever a shell file changes** — the page, the CSS, the app, the four data files, the teaching data or a glyph — and keep the two `?v=` numbers in `index.html` identical to it. A student with an active worker reads the shell from a cache named after that version, so new content reaches them when the name changes and not before. The worker never caches a dev harness or anything a harness loads, so `preview.html` and `mobile.html` keep showing the file on disk.
