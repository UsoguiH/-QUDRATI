# قدراتي — QUDRATI

**This is a real, published project. It is live at [qudrati.xyz](https://qudrati.xyz/) and available on Android as `Qudrati.apk`. Treat all changes as production code.**

## What it is

A Duolingo-style Arabic web game for practicing the Quantitative section of the Saudi General Aptitude Test (GAT / Qiyas). Fully RTL, Arabic-first, zero dependencies, zero server, zero build toolchain. Open `index.html` and play.

## Tech stack

- **Pure HTML/CSS/JS** — no npm, no bundler, no framework
- **State**: single `S` object in `localStorage["qudratState"]`
- **CSS**: pixel-perfect implementation of the Duolingo design system (colors/radii extracted from Figma file `sCGqaL307LkNrY35xnV66O`)
- **Font**: Baloo Bhaijaan 2 (Arabic rounded equivalent of Duolingo's DIN 2014 Rounded VF)
- **Android**: Capacitor wrapper → `Qudrati.apk`

## Game systems

- **Structure**: 4 units · 26 lessons (8 / 5 / 4 / 9), unlocked sequentially; a lesson serves 8 questions
- **Teaching cards** (`js/data/teach.js`, all 26 lessons): a chunk = 2–3 rules + one quick check (no hearts, no timer, no XP, never writes `qstats`), shown right before the first question that needs it; the queue is regrouped by chunk. A rule card shows `say` (the rule in plain words), an optional figure from `teach-figures.js`, the `plain` chip (the formula in words — no bare letters; the exact `formula` stays in the guidebook), the `example`, and the `hook` memory line. A figure must use the same numbers as the card's `example`. Lessons without cards still show the old full-rules intro. «دفتر القوانين» (one lesson's rules, missed/taught first) opens from the «كيف أحلّها؟» sheet; the unit banner's «القوانين» button (the guidebook glyph, `assets/icons/guide.svg`) opens every lesson's rules of that unit in one sheet. Cards navigate with a bottom bar («السابق» / «التالي»): «السابق» is the white secondary button, faded on the first card and live everywhere else, the answered check included. The check's answer plays the lesson's GSAP jump (right) or drop-and-shake (wrong), without strike, confetti, or streak tag. Validate with `node tools/validate_teach.js`.
- **Mascot «قدّور»** (`assets/mascot/`, helper `mascot(state, cls)` in app.js): a flat cartoon teacher with a pointer stick and a purple «قدرات» book. **Exactly three placements and nothing else** (the user cut the rest on 2026-09-09 — the path, the hello screen, the modals — do not add him anywhere else): the **value screen** «إليك ما ستحصل عليه», where `point` stands beside the speech bubble (`iv-mascot`; the user asked for this one back the same day, keep it), the **win screen**, where `celebrate` replaced the streak flame (`winHero()` + `winHeroPlay()`, GSAP, the same grammar as the card's `fxAddJump`: he drops in from above and lands hard as the title pops, then cheers in a rhythm — hop, hop, a sway — with anticipation, stretch, hang time, squash and a back-out settle, over a live shadow that shrinks in the air and spreads on impact. **Nothing behind him and no confetti, rings or particle sprays, ever**: the user calls that AI slop; the character is the celebration), and the **mock exam home** card, where `strong` stands ready (`mhReady` entrance, then breathes). `MASCOT_STATES` gates the three files (`celebrate`, `strong`, `point`); an unlisted state renders nothing. Motion is CSS only, off under `data-motion="reduced"`. He is never mirrored (`scaleX(-1)` reverses the book's Arabic). The full 14-pose sheets stay in `assets/mascot/sheets/`; `tools/slice_mascot.py` cuts them but writes only `SHIP`.
- **Questions**: 255 original questions — MCQ (`format:"mcq"`) and comparison (`format:"comparison"`, 35 of them). Difficulty is **per question**: a question line in the markdown may carry a star marker between its number and its stem (`**٨)** ★★ ما قيمة …`), and falls back to the lesson's ★ rating when it has none, so the ramp can be authored lesson by lesson. The app serves a lesson's questions easiest-first inside each teaching chunk
- **Tracks**: `"sci"` (scientific) and `"lit"` (literary — lighter quant load, excludes `track:"sci"` questions)
- **Hearts**: 5 per level; losing all resets the level. Review, the mix and the placement test run without hearts or a timer (`NO_FAIL`), and the header shows a question count there instead of «٩٩٩»
- **Timer**: 60 seconds per question (matches real GAT pace) — shown as a Duolingo-style pill (tinted capsule, the Figma clock with its hand spinning, m:ss); green at rest, yellow at ≤15s, red at ≤5s
- **Gems** (`S.xp`): spendable currency — revive (50), 2× boost (50)
- **Rank XP** (`S.totalXp`): lifetime total, never decremented; drives the 5 rank tiers (bronze → silver → gold → diamond → champion)
- **Streak**: daily streak with Rive flame animation
- **Stars**: 1–3 per lesson
- **Wrong-answer queue**: incorrect questions are replayed at session end
- **Daily quest**: the student's own goal — ٥، ١٠ or ٢٠ questions (`GOALS`, `S.goal`, `dailyGoal()`; ١٠ by default), chosen from Settings. The chest pays in proportion (`chestGems()`: ٢٥ / ٥٠ / ١٠٠ gems) and the ceremony's pyramid is built from that count, never a fixed fifty. The chest is navy with gold trims (`CHEST_PAINT` in app.js; `chestSVG()` draws the small icon on the path and the quest card). Opening it (`A.openChest`) plays a frame-measured clone of Duolingo's chest ceremony on a fixed 480×1044 stage scaled to the phone (`.chest-veil > .cv-stage`): three taps, each with a leap and a comet arc, the third opens it, light pours out, a white wash, then the 50-gem pyramid and the counter ticking up; «المتابعة» claims. Sound cues are synthesized on the app's audio context and gated by `S.sound`; reduced motion jumps straight to the reward. The tenth answer of the day drops a white quest card from the top of the lesson (`A.questBanner`: the chest, «اكتمل تمرين اليوم!», the day's bar filling its last step) — never a toast; tapping the chest early on the path answers in a speech bubble (`chestTip`). `chest-animation.html` at the root is the standalone playground it was ported from (rare/epic/legendary tiers and 18 colourways live only there).
- **League**: ghost leaderboard opponents, rebuilt from the week number on every draw — nothing about them is stored
- **Review** (`S.mistakes`): a missed question is due at once; one correct answer pushes it two days out (`SRS_GAP`), a second correct answer on a later day retires it. The path's due card counts what is waiting, and lessons whose last play is three weeks old show a refresh glyph
- **Daily mix** (`A.startMix`, `MIX_N`): ten questions weighted toward the weakest domain that has at least one opened lesson — offered once the student has answered enough for the accuracy to mean something
- **Placement** (`A.startPlacement`, `PLACE_PER_UNIT`, `PLACE_PASS`): three questions per unit, one pass, no hearts and no timer; every unit it passes is unlocked and starred. Offered once on the first run, and re-runnable from Settings, where it can only ever add
- **Backup codes**: «نسخة احتياطية» in Settings encodes the whole save into one string (`BACKUP_TAG`, base64); restoring shows what is about to be overwritten before it does it
- **Offline and installable**: `sw.js` precaches the shell, so a lesson survives losing the network; the path says so in a note rather than failing silently (`netBar`). `beforeinstallprompt` is kept, not swallowed, and Settings offers «ثبّت التطبيق على جهازك» (`A.installApp`)
- **Reporting a question** (`S.reports`): «أبلغ عن هذا السؤال» under every wrong answer, five reasons, kept in the save and listed in Settings ready to copy. There is no server, and the copy never pretends otherwise
- **Mock exam**: 2 sections × 25 min, free navigation + flagging (mirrors real GAT computerized format); an interrupted mock is resumable (`MOCK_KEY`, `A.mockResume`)

## Question schema

```js
{
  id: "unique-id",           // e.g. "oo-01" — must be globally unique
  format: "mcq",             // or "comparison"
  difficulty: 2,             // 1=easy, 2=medium, 3=hard
  track: "both",             // "both" | "sci" | "lit"
  stem: "نص السؤال…",
  choices: ["أ","ب","جـ","د"], // mcq only — 4 items, no letter prefix
  // value1: "…", value2: "…", // comparison only
  answer: 0,                 // 0-indexed correct choice
  solution: "الحل خطوة…",   // step-by-step, \n between steps (≥10 chars)
  method: "١) …\n٢) …\n💡 …", // structured method steps (optional but preferred)
  figure: null               // or inline SVG / HTML table string
}
```

Lessons also carry `stars`, `xp`, `pages`, `category`, `goal`, `rules[{n,name,formula,when}]`, `notes`,
`tricks`, an optional `figure`, and a flat `method` string (the fallback the method sheet shows).

Comparison answers must use the fixed 4-choice set defined in `CMP_CHOICES` (app.js line ~12):
`["القيمة الأولى أكبر", "القيمة الثانية أكبر", "القيمتان متساويتان", "المعطيات غير كافية"]`

## Validating the question bank

```bash
node tools/validate.js
```

Checks: unique IDs, valid format/difficulty/track/answer, solution length, figure tag, duplicate choices, comparison answer distribution.
The difficulty ramp is checked by `node tools/validate_teach.js` instead, which knows the chunks: a
student meets a chunk's questions sorted by difficulty, so that validator lists every step wider than
one star as a cliff still to bridge.

**The four data files are generated — never hand-edit them.** To change content, edit
`qudrat-lessons-duolingo.md` and run:

```bash
python tools/import_curriculum.py          # --check parses and reconciles without writing
node tools/validate.js
```

The importer refuses any line it cannot parse and reconciles every count against the
file's own map; a question that says «في الشكل» must have an SVG in `tools/curriculum_figures.py`.

## Adding features

- All rendering is done by functions in `js/app.js` that return HTML strings and set `$app.innerHTML`.
- Navigation: call `A.go(screenName)` — the `A` object exposes all public handlers.
- New screens follow the pattern: render function → attach to `A` → add nav target to `A.go()`.
- CSS variables are at the top of `style.css` under `:root`. Always use them — never hardcode colors.
- Arabic digits: use `toAr(n)` to render numbers in Eastern Arabic (`٠١٢٣٤٥٦٧٨٩`). Use Latin digits only in code/IDs.

## What NOT to do

- Do not introduce any npm packages, bundlers, or build steps — the project ships as static files.
- Do not add `//`-commented-out code blocks or TODO comments in production code.
- Do not use Latin digits in user-visible text (question stems, solutions, UI).
- Do not copy or reproduce real Qiyas/ETEC exam questions — all questions must be original.
- Do not break the RTL layout — test all UI changes with `dir="rtl"`.

## Deployment

Static hosting, no server required. The app is live at **qudrati.xyz**. The Android APK (`Qudrati.apk`) is a Capacitor wrapper over the same static files.

**Bump `VERSION` in `sw.js` whenever a shell file changes** — the page, the CSS, the app, the four data files, the teaching data or a glyph — and keep the two `?v=` numbers in `index.html` identical to it. A student with an active worker reads the shell from a cache named after that version, so new content reaches them when the name changes and not before. The worker never caches a dev harness or anything a harness loads, so `preview.html` and `mobile.html` keep showing the file on disk.

### SEO / AEO

- The canonical host is `https://qudrati.xyz/` (`<link rel="canonical">`, `og:url`, sitemap, and the www → apex redirect in `vercel.json` all agree). Keep them agreeing.
- The head carries JSON-LD (`Organization` with the logo, `WebSite`, `WebPage`, `WebApplication`). No `FAQPage` on the home page: its FAQ is only in the pre-render, which the app never shows. The guide page keeps its own FAQ + FAQPage, visible and matching.
- Every dev page (`preview.html`, `mobile.html`, `mascot-*.html`, `exam-date-picker.html`, `quiz-two-bolts.html`) carries `<meta name="robots" content="noindex, nofollow">` because Vercel deploys the whole tree. Give any new dev page the same tag.
- `llms.txt` is the plain-text summary answer engines read; it repeats the landing copy and the FAQ.
- `84edf0824abfca4d5ac34f205827cd10.txt` at the root is the IndexNow key (Bing, DuckDuckGo, Copilot, ChatGPT search all read Bing's index). After a content change, ping `https://api.indexnow.org/indexnow?url=https://qudrati.xyz/&key=84edf0824abfca4d5ac34f205827cd10` and the page is recrawled within hours instead of weeks. Google does not use IndexNow.
